# subgoal-export-js-docs.md

Derived from master GOAL.md / acceptance criterion: "Exports are documented as templates, not drop-in production code."

## Problem
`exportScrollTriggerJS()` generates JS with hardcoded frame paths (`/frames/frame-XXXX.webp`) and no clear notice that consumers must replace them. Looks like production-ready code but is a template.

## Goal
Add clear documentation/comments that the generated JS is a starter template requiring frame URL replacement.

## Verification Gates
- [ ] Generated JS comment block states frames must be replaced with actual URLs
- [ ] `exportScrollTriggerJSON`/`CSS`/`JS` all carry a "generated by Artisan Labs" header
- [ ] `pnpm tsc --noEmit` passes

## Files to Touch

## Non-Goals
- Auto-downloading frame images
- Frame sprite generation
